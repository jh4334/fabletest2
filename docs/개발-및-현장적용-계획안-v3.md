# 《마음의 문》 v3 개발 및 현장 적용 계획(안)

## 1. 사업 개요

- 사업명: 초등학생을 위한 AI·디지털 시민의식 게임 《마음의 문》 v3 고도화
- 개발 형태: 브라우저 기반 2D 스토리 어드벤처·방탈출·턴제 마음 조각 배틀
- 적용 대상: 초등학교 학생 및 지도 교사
- 운영 형태: GitHub Pages 배포, PWA 설치 및 오프라인 실행
- 기준 버전: PR #68 「전 챕터 비주얼 에셋과 스토리 전면 개편」
- 개발 기간: 착수일로부터 10주
- 현장 적용: 연구학교 3개교 파일럿 후 개선 버전 공개

## 2. 추진 배경

기존 AI 윤리 교육 자료는 개념 설명과 정답 확인에 치우치기 쉽다. 《마음의 문》은 학생이 교육용 프로그램을 사용한다는 부담 없이 모험하고, 인물의 감정을 듣고, 행동으로 문제를 해결하는 과정에서 AI·디지털 시민의식의 핵심 개념을 경험하도록 설계한 게임이다.

v3에서는 전 챕터 에셋과 보스 표정을 통일하고, 프롤로그부터 네 가지 엔딩까지 이야기를 하나의 감정선으로 연결했다. 다음 단계에서는 새 에셋과 개편된 서사가 실제 플레이 흐름에서 자연스럽게 작동하는지 검증하고, 16차시 수업 자료·교사용 기능·현장 적용 절차를 하나의 운영 체계로 완성한다.

## 3. 추진 목적

1. 여덟 인물과 다섯 챕터·파이널의 시각적 완성도를 일관되게 높인다.
2. AI 윤리 개념을 설명문이 아닌 탐험·선택·결과로 경험하게 한다.
3. 학생용 모험 화면과 교사용 학습 관리 기능을 명확히 분리한다.
4. 저사양 PC와 태블릿에서도 설치 없이 안정적으로 실행되게 한다.
5. 3개 학교 파일럿을 통해 재미·이해·수업 운영성·접근성을 검증한다.
6. 개인정보를 외부 서버로 전송하지 않는 안전한 교실용 배포 모델을 유지한다.

## 4. 핵심 개발 방향

### 가. 게임은 먼저 재미있어야 한다

- 교육 용어를 앞세우지 않고 인물의 욕망과 공간의 문제를 먼저 보여 준다.
- 각 챕터는 탐색, 세 구역의 행동 퍼즐, 보스와의 대화, 다음 기억의 발견으로 마무리한다.
- 같은 정답을 반복 선택하는 구조보다 보스마다 다른 움직임과 행동 규칙을 제공한다.

### 나. 모든 챕터는 하나의 이야기로 이어진다

`남의 목소리 → 소유 → 편한 시선 → 거짓 확신 → 관심 → 집착 → 침묵 → 책임`

따라부터 고요까지의 일곱 인물은 영이가 견디지 못해 떼어 놓은 마음이며, 여덟 번째 인물인 영이는 흩어진 마음을 다시 마주하고 자신의 다음 길을 결정한다. 각 장의 승리 장면에는 다음 기억을 여는 단서를 배치해 독립된 수업처럼 끊기는 느낌을 줄인다.

### 다. 선택권과 책임을 함께 다룬다

- 학생이 어른의 잘못을 대신 면책하지 않게 한다.
- 박사는 영이를 방치하고 폐기 결정에서 도망친 책임을 직접 인정한다.
- 영이의 귀환, 자립, 작별을 단순한 정답·오답으로 평가하지 않는다.
- 따뜻한 선택의 의미는 상대를 소유하는 것이 아니라 듣고 기다리는 태도로 표현한다.

### 라. 교실 운영은 단순하게 유지한다

- 학생은 링크 접속 또는 홈 화면 추가만으로 실행한다.
- 교사는 타이틀의 「선생님 방」에서 수업 모드, 진도, 진단, CSV를 사용한다.
- 계정, 로그인, 결제, 외부 데이터베이스는 도입하지 않는다.
- 저장 데이터는 기기 내부에 두고 필요할 때 교사가 백업 파일로 관리한다.

## 5. 개발 범위

### 5.1 학생용 게임

- 프롤로그, 1~5장, 고요의 뜰, 코어, 네 가지 엔딩
- 챕터별 방탈출 구역 3개와 전용 행동 퍼즐
- 여덟 보스의 표정·배틀 연출·대사·후일담
- 반디의 동행, 복선, 정체 공개와 부재 연출
- 일곱 일기 조각, 친구 수첩, 기억 조각, 도전과제
- 난이도, 큰 글씨, 색약 모드, 읽어주기, 저사양 모드
- 키보드·터치·가상 스틱 및 가로 화면 대응

### 5.2 교사용 기능

- 학년별 난이도와 챕터 바로 시작
- 학생별 진행도·정답률·자비·복습 현황
- 약점 주제와 추천 차시를 연결한 진단 리포트
- 사전·사후 점검과 결과 CSV 내보내기
- 커스텀 퀴즈 등록과 수료증 생성
- 데이터 백업·복원 및 교실 기기 교체 대응

### 5.3 수업 자료

- 16차시 교수·학습 흐름과 게임 구간 대응표
- 차시별 지도안, 활동지, 교사 발문
- 수업 전 기기 점검표와 5분 교사 온보딩
- 학생용 조작 안내와 문제 발생 시 복구 안내
- 현장 적용 관찰지, 학생 소감지, 교사 피드백지

### 5.4 이번 단계에서 제외하는 범위

- 학생 회원가입과 온라인 계정
- 외부 서버에 학생 이름·성적·플레이 기록 저장
- 실시간 채팅과 생성형 AI 자유 대화
- 유료 결제, 광고, 온라인 경쟁 순위
- 현재 다섯 챕터와 파이널을 넘어서는 신규 장 추가

## 8. 품질 기준

### 기능·안정성

- `npm run validate`, `npm test`, 플레이봇, 브라우저 스모크 전체 통과
- 프롤로그부터 네 가지 엔딩까지 진행을 막는 오류 0건
- 기존 세이브 로드와 백업·복원 성공
- 이미지 로딩 실패 시 기존 도트 그래픽으로 정상 대체
- 서비스워커 캐시와 실제 정적 자산 목록 일치

### 사용성·접근성

- 교사가 설명하지 않아도 첫 조사와 첫 이동 가능
- 터치 목표 크기와 가상 스틱 오조작 점검
- 큰 글씨에서 대사·선택지·표가 화면 밖으로 잘리지 않음
- 색상만으로 정답, 위험, 진행 상태를 구분하지 않음
- 읽어주기와 자막 속도 조절이 주요 대사에 적용됨

### 스토리·교육성

- 학생이 각 보스의 행동 이유를 자기 말로 설명할 수 있음
- 1~5장 연결 단서와 영이의 정체가 뒤늦게 하나의 이야기로 이해됨
- 박사와 영이의 책임·선택권이 혼동되지 않음
- 교육 개념을 몰라도 퍼즐을 진행할 수 있고, 플레이 후에는 개념을 회상할 수 있음
- 엔딩이 단순한 점수 보상보다 여정의 태도와 연결되어 보임

## 9. 파일럿 평가 지표

다음 값은 목표 또는 기록 항목이며, 실제 결과는 파일럿 종료 후 입력한다.

| 영역 | 기록 지표 | 목표·입력 |
| --- | --- | --- |
| 접근성 | 첫 이동·조사 성공률 | 90% 이상 |
| 안정성 | 수업을 중단시키는 오류 | 0건 |
| 운영성 | 교사 최초 준비 시간 | 10분 이내 |
| 몰입 | 차시 중 게임 이탈 학생 비율 | 10% 이하 |
| 이해 | 보스 행동 이유 설명 가능 학생 | 70% 이상 |
| 학습 | 사전·사후 점수 변화 | `[추후 입력]` |
| 만족도 | 학생·교사 만족도 | `[추후 입력]` |
| 개선 | 반복 관찰된 불편·오류 | `[추후 입력]` |

수치는 학급 규모와 적용 방식에 따라 해석하며, 결과를 과장하지 않고 응답 인원과 측정 조건을 함께 기록한다.

| 교사 운영 부담 증가 | 5분 온보딩, 차시 바로 시작, 문제 해결 체크리스트 제공 |

### 구현 완료

- 전 챕터 바닥·랜드마크와 플레이어·반디·여덟 보스 표정 에셋 적용
- 따라~영이의 이야기 축, 박사 책임, 고요 정체, 장간 단서, 네 엔딩 개편
- 선생님 방 수업 모드에 프롤로그 추가 및 프롤로그 사전·사후 점검 연결
- 수업 구간 화면에 16차시 번호·핵심 관점 표시
- 1~16차시 활동지와 실제 맵·플래그 대응표 작성
- 교사·학생 관찰지, 기기표, 지표 계산을 포함한 파일럿 운영팩 작성
- 에셋·사운드·오프라인 캐시·16차시 추천을 검사하는 출시 게이트 추가
- README, 교사 온보딩, 진단 스펙, 출시 체크리스트, 에셋 출처 최신화

### 자동 검증

- 데이터·어휘·좌표·스토리 정합성: `npm run validate`
- 에셋·캐시·차시·사운드 정합성: `npm run releasecheck`
- 전체 로직·세이브 회귀: `npm test`
- 프롤로그~진엔딩 완주: `npm run playtest`
- 데스크톱·모바일·오프라인 렌더: `npm run test:browser`
