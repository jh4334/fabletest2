# 《마음의 문》 v3 출시 후보 QA 리포트

## 1. 범위와 판정

대상은 학생 흐름 `타이틀 → 탐험 → 마음 조각 배틀 → 장 마무리 → 파이널`
과 교사 흐름 `선생님 방 → 수업 구간 → 사전 점검 → 플레이 → 사후 점검 →
진단·CSV`입니다.

현재 판정은 **내부 출시 후보·파일럿 준비 완료 조건 검증 중**입니다. 실제 학교
파일럿 결과와 iPad·Android 실기기 체감은 아직 입력하지 않습니다.

## 2. 이번 개편에서 확인한 문제와 처리

| 우선순위 | 확인한 문제 | 처리 |
| --- | --- | --- |
| P1 | 16차시를 약속하지만 활동지는 5차시뿐 | 1~16차시 활동지와 구간 대응표로 전면 교체 |
| P1 | 문서에는 프롤로그 수업 시작이 있으나 게임 선택기에 없음 | 프롤로그 시작 상태·사전/사후 추가 |
| P1 | 사전 점검 뒤 선생님 방으로 돌아가 실제 수업 시작이 끊김 | 완료·건너뛰기 모두 선택 구간 월드로 이동 |
| P2 | 진단 리포트가 모든 주제를 기존 5차시 묶음으로 추천 | 28개 주제를 16차시 개별 추천으로 재정렬 |
| P2 | 수업 모드 화면에서 오늘 차시와 장의 관계를 알기 어려움 | 7개 구간마다 연계 차시와 핵심 관점 표시 |
| P2 | 에셋·캐시·차시 문서가 서로 어긋나도 기존 CI가 놓침 | `releasecheck`와 CI 게이트 추가 |
| P3 | README가 외부 이미지 파일이 없다고 잘못 안내 | 로컬 PNG·CC0 타일 구조로 수정 |

## 3. 화면 증거

현재 실행에서 node-canvas로 23개 제품 화면과 6개 교사 온보딩 화면을 다시
렌더했습니다.

- 핵심 화면: `shots/01-title.png`, `02-world.png`, `04-battle.png`,
  `06-dodge.png`, `08-ending.png`, `22-classmode.png`, `23-report.png`
- 교사 흐름: `shots/onboarding-1-title.png`~`onboarding-6-report.png`
- 타이틀: 여덟 인물의 색·실루엣이 한 줄에서 구분되고 슬롯과 겹치지 않음
- 수업 모드: 프롤로그 제목, 구간 설명, 16차시 연결, 조작 안내가 서로 겹치지 않음
- 배틀: 보스 표정·마음 게이지·행동 메뉴·하트의 계층이 유지됨

이 환경의 node-canvas에는 한국어 글꼴이 없어 캡처의 한글이 네모로 표시됩니다.
따라서 정적 캡처로 위치·색·이미지 배치는 확인했지만, 실제 한글 글꼴의 자간과
획 가독성은 Chromium CI와 실기기에서 다시 확인해야 합니다. 로컬 Playwright는
브라우저 바이너리 다운로드가 빈 파일로 차단돼 실행하지 못했습니다.

## 4. 비주얼·에셋

- 플레이어, 반디, 보스 8종 시트가 모두 `art.js`에 등록됨
- 보스 시트는 같은 627×627 RGBA 규격과 네 감정 상태를 사용
- 모든 등록 이미지가 서비스워커 프리캐시에 포함됨
- 이미지 총량은 출시 점검 상한 5MB 안
- 이미지 실패 시 절차적 도트 스프라이트로 폴백
- 30개 주요 챕터 맵은 기존 충돌·타일 문자를 바꾸지 않고 같은 CC0 바닥 계열 사용

## 5. 사운드

- 보스 8종 모두 전용 `boss_*` 곡을 사용
- 각 곡의 트랙 길이가 같아 반복 경계가 어긋나지 않음
- 보스 곡 트랙 음량 합은 0.16~0.30 범위
- 고요는 의도적으로 가장 작고, 영이는 3성부 완전판으로 가장 풍성함
- 음량 3단계, 음소거, 효과 줄이기와 독립적으로 동작

실제 교실의 여러 기기 동시 재생은 자동 측정할 수 없으므로 운영팩에서 기본
음량을 낮추고 실기기 점검을 남깁니다.

## 6. 스토리·플레이 흐름

- 오프닝의 구조 신호가 첫 목표를 만들고 따라까지 이어짐
- 따라~고요의 일곱 마음, 코어의 7/8 의자, 영이의 여덟 번째 자리가 일치
- 1~5장 승리 뒤 다음 장 기억 단서가 한 줄씩 이어짐
- 박사는 방치와 폐기 결정에서 물러난 책임을 직접 인정함
- 고요는 영이가 남겨 둔 침묵으로 명시됨
- 반디 공개 뒤 영이 전투와 네 엔딩이 귀환·자립·작별·침묵의 선택으로 연결됨
- 학생이 어른의 책임을 대신 면책하는 선택지는 없음

## 7. 수업·교사 흐름

- 프롤로그~파이널 7개 시작 상태와 실제 맵·플래그를 대응표에 고정
- 프롤로그·1~5장은 같은 5문항의 사전·사후 점검을 선택적으로 제공
- 파이널은 객관식 점수 대신 엔딩 이유와 자기 원칙을 서술형으로 기록
- 모든 퀴즈 주제가 1~16차시 추천 중 하나에 연결됨
- 수업 점프는 현재 슬롯을 바꾸므로 적용 전 백업 경고 유지
- CSV·백업·진단은 로컬 처리하며 학생 실명 사용을 요구하지 않음

## 8. 접근성·반응형

코드와 자동 검사로 확인한 항목:

- 큰 글씨 줄바꿈, 색약 보조 표기, 읽어주기, 화면 효과 줄이기
- 모바일 세로 회전 안내, 가로 터치 UI, 44px 이상 터치 목표
- 멀티터치 버튼·스틱 소유권, 노치 안전 영역
- 저사양 모드와 장식 효과 축소

남은 실기기 확인:

- VoiceOver·TalkBack의 캔버스 주변 탐색 순서
- 768px급 태블릿에서 스틱과 A 버튼의 동시 조작감
- 밝은 교실에서 황혼 장면의 명암
- 여러 기기 동시 재생 시 음량

## 9. 자동 검증 게이트

최종 커밋 전 아래 명령을 모두 실행합니다.

1. `npm run bump`
2. `npm run validate`
3. `npm run releasecheck`
4. `npm test`
5. `npm run playtest`
6. `npm run test:browser` — 로컬 환경 실패 시 GitHub CI에서 필수 통과
